## 1. 删掉「学员申请」tab

- 左侧导航只剩 总览 / 计划编排 / 动作库 / 追踪。
- 红色计数挪到「总览」上，数字 = 有待处理事项的**学员人数**（申请人算一人；只有「落后」的学员不算）。
- 兜底：本机记住的上次页面是 `requests` 的，进来落到总览；⌘K 搜「申请 / 学员申请」跳总览；面包屑不再出现「学员申请」。

## 2. 待处理区（总览顶部）

- 位置：总览最上方单独一块，下面接现有学员看板（筛选、列、快捷键一律不动）。
- 标题行：「待处理」+ 红色计数 + 「每 60 秒自动刷新」+ 右侧「我的邀请码 ×××× 复制」。邀请码从原申请页底栏搬来，任何状态都在。
- 四组，固定顺序：**学员申请 → 计划快结束 → RPE 超标 / 未完成 → 留言**。空组不显示。每组最多 3 条，其余收进「展开其余 N 条」。
- 全部为空时整块收成一行：「暂无待处理 · 学员输入邀请码后，申请会出现在这里」+ 邀请码。
- 还没有学员时：只有待处理区；看板位置显示「接受申请后，学员会出现在这里」。

## 3. 四组的内容与消失规则

| 组 | 一条显示什么 | 点它去哪 | 什么时候消失 |
|---|---|---|---|
| 学员申请 | 沿用现申请卡：头像、名字、手机尾号·时间·邀请码、自报 1RM 摘要；可展开入驻资料；接受 / 拒绝原地完成 | 原地处理 | 接受（学员进看板）或拒绝 |
| 计划快结束 | 学员名 ·「计划名」还剩 N 天 / 已结束 N 天 +「排下一份 →」 | 该学员计划编排 | 发布了下一份计划（点进去不消失） |
| RPE 超标 / 未完成 | 学员名 + 最新一条（如「W2D3 深蹲 第 3 组 RPE 9.5 · 目标 8」「W2D2 卧推 第 5 组未完成」）+「另 N 条」；落后单独一行灰字「W2D1 推荐 10-19 还没练」+「去后移」 | 该学员计划编排；「去后移」= 打开并展开那一天、后移面板直接展开 | 教练打开该学员计划编排即消失（调 `plan-viewed`）；之后新发生的再出现 |
| 留言 | 学员名 + 未读数 + 最新一句（截断一行） | 该学员计划编排的聊天 | 读了即消失（沿用现有已读） |

- 口径（后端算，前端不重算）：计划快结束 = 剩 ≤3 天且后面没接上已发布计划；RPE 超标 = 实际 ≥ 目标 + 1（区间比上限）；未完成 = 已完成训练日里处方组没做完或失败；落后 = 推荐日期已过还没练。只看最近 7 天。
- 「落后」是轻提示：灰字、不计红色计数。

## 4. 后移按钮挪到右上角

训练日展开卡的「后移…」从底部操作提示栏挪到卡片右上角（按周排、按天排都是）。面板内容、交互、撤销不变。

## 5. 刷新与失败

- 提醒随现有 60 秒可见轮询一起刷新；从计划编排回到总览立即刷新一次。
- 提醒接口失败：该三组位置显示一行「提醒加载失败 · 重试」，不影响申请组和看板。
- 后端未部署本接口（404）时三组静默不显示，申请组照常——网页可以先于后端上线。

## 验收清单

1. 导航没有「学员申请」；总览红色计数 = 有待处理事项的学员数（只落后的不算）。
2. 本机上次停在申请页 → 刷新后落总览；⌘K「申请」跳总览。
3. 有 2 条申请：待处理区显示两张申请卡，展开、接受、拒绝与原申请页行为一致；接受后卡消失、学员出现在看板。
4. 邀请码在任何状态（有事项 / 全空 / 零学员）都看得到且能复制。
5. 计划快结束：一条显示剩余天数，点「排下一份」进该学员编辑器；回总览仍在；发布下一份后消失。
6. RPE 超标 / 未完成：显示最新一条 + 另 N 条；点进该学员编辑器再回总览，该学员这一组消失。
7. 落后：灰字、不计数；「去后移」打开该学员编辑器、展开那一天、后移面板已展开。
8. 留言：显示未读数与最新一句；读完回总览消失。
9. 每组超过 3 条出现「展开其余 N 条」；空组不出现；全空收成一行。
10. 零学员：只有待处理区 + 看板位置的一句提示。
11. 提醒接口失败显示重试；404 时静默；两种情况下申请组和看板正常。
12. 训练日展开卡右上角是「后移…」，底部不再有；后移、撤销行为不变（按周排 / 按天排都验）。
13. 老教练升级后第一屏：总览正常、待处理区按真实数据出现，没有报错或空白。
14. 中文、英文（018 合入后含繁体）文案齐全。
