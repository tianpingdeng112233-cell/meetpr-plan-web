# 020 — 反馈入口常驻顶栏 + 整日反馈

- **状态**: Spec 已确认（2026-10-24），屏幕稿待「定稿」，未派卡
- **来源**: 内测教练反馈「给学员反馈的地方要找半天」「只能按组反馈，想对整日训练反馈」。David 2026-10-24 /grill 两轮 9 题后「确认」，逐题记录 `~/Projects/scratch/day-feedback-grill-20261024.md`。
- **前置**: spec 013（反馈模式、视频标记）、011（历史栏）、014（按天排）均已上线。本 spec 只在 013 的反馈模式上加东西，013 已有行为不变。
- **级别 / 节奏**: T2 / P1。**只改网页**：后端、iOS、安卓都不改。本仓无 CI，合并闸门 = 本地全量测试 + `tsc --noEmit` + build + Opus 浏览器亲验。
- **屏幕稿**: 待出，定稿后结构与文案转写到文末「屏幕稿」，实装以转写为准。

## 0. 为什么

1. **找不到**：现在网页上唯一的反馈入口是历史栏顶的「▶ 待看 N」，字面没有「反馈」，历史栏收起时不显示；回复框要先开一段视频才出现。教练不知道在哪给学员写反馈。
2. **只能按组**：反馈只能挂在某一组的视频上，没有视频就没地方写，也没法对一整天的训练说话。

## 现状事实（已核实，不需要改）

- 后端 `POST /coach/feedback` 的 `plan_exercise_id`、`video_id` 都可为空，只带 `day_date` 即为整日反馈；`GET /students/:id/feedback` 教练可读自己给该学员的全部反馈（含 `day_date`、`posted_at`、`read_at`）。
- 两端学员 App 的反馈列表 / 详情已经显示只带日期的反馈（标题落到日期）。iOS 教练端早已能按日期发。
- 发反馈不推送通知（现有视频反馈同样），本期不改。
- 网页 `CoachFeedbackPayload.video_id` 目前声明为必填 `string`，要放宽为可空——这是本仓类型，不是接口变化。

## 术语（已写入 `CONTEXT.md`）

- **整日反馈**：教练对学员某个已完成训练日整体写的反馈，只挂日期，不挂动作 / 组 / 视频；同一天可多条。
- **反馈模式**：定义更新为「栏内放训练日列表、待看列表、打点和回复」，入口为顶栏「反馈」与历史栏「反馈 · 待看 N」。

## 1. 入口

- **顶栏「反馈」按钮**：计划编排顶栏常驻（位置以屏幕稿为准，建议在「显示实际」开关左边），文字就是「反馈」，带角标 = 当前学员**待看视频**数（0 不显示角标）。历史栏收起时也在；只读计划同样有。
  - 点击：进入反馈模式。有待看视频 → 同 013 现行为播放第一段待看；没有 → 只进入反馈模式，不开视频窗，训练日列表滚到最底（最近一天）。
  - 已在反馈模式时再点 = 退出（同「← 历史」）。
- **历史栏入口改名**：「▶ 待看 N」→「反馈 · 待看 N」，行为不变。
- 角标口径**只算待看视频**，不算「已练未反馈的天」。导航项徽标口径（013 §1）不变。

## 2. 反馈模式里的「训练日」

### 2.1 位置与内容
- 反馈模式栏顶（「← 历史」那一行）下面，新增一节「训练日」，在 013 的待看列表**上方**。
- 列**当前打开计划里学员已完成的训练日**（未完成 / 未来的天不列，不能写整日反馈）。
- **排序：按训练日期升序，最近练的排最下面**。这一节自己滚动（高度以屏幕稿为准），进入反馈模式时滚到最底。
- 每条写「W2 · D3 · 10/22」（周 · 第几天 · 实际训练日期）；该天还没有任何整日反馈 → 条目带一个小点；已有 → 显示条数。
- 悬停 / 选中一条 → 网格上那一天的列头（按天排时为行头）同步高亮，必要时滚到可见；与 013 待看列表的积木高亮同一套样式。

### 2.2 写整日反馈
- 点一条训练日 → 选中它；栏底回复区切到这一天：
  - 回复区上方列出这一天**已发的整日反馈**，按发送时间升序，每条「时间 · 文字 · 已读 / 未读」。
  - 输入框占位文案对着这一天（例「给 W2 · D3 的整体反馈…」，最终以屏幕稿为准）；「发送反馈 ⌘↵」。
  - 发送 = `POST /coach/feedback`，`{ student_id, day_date: 该天实际训练日期, plan_exercise_id: null, video_id: null, text }`。成功后清空输入框、追加到列表、小点消失 / 条数 +1；失败保留输入并提示重试。
- 选中训练日与播放视频互斥：选中训练日时关闭竖屏大窗；点待看列表里的视频则取消训练日选中，回复区回到 013 的视频反馈。
- `day_date` 取该训练日学员**实际训练的日期**（学员记录的日期），不是推荐日期。
- 同一天可写多条；不能编辑、删除已发的反馈。

### 2.3 数据
- 整日反馈的读取用 `GET /students/:id/feedback`，按 `plan_exercise_id == null && video_id == null && day_date != null` 筛出，再按 `day_date` 对到训练日。对不上本计划任何训练日的不显示。
- 加载失败：训练日列表照常显示（不带条数 / 小点），节头给重试；不影响编辑和视频反馈。

## 3. 网格上的「已反馈」标记

- 有整日反馈的那一天，列头（按周排）/ 行头（按天排）显示一个小的「已反馈」标记，扫视态和编辑态都显示。
- 悬停标记：提示框列出该天所有整日反馈（时间 · 文字，过长截断）。
- 点击标记 = 进入反馈模式并选中这一天。
- 样式安静（遵守 011 §6「编辑器不用橙色，淡黄可用」），不和视频标记抢眼；以屏幕稿为准。

## 4. 切换学员 / 计划

- 沿用 013 §3.5：切学员退出反馈模式；切同一学员另一份计划时反馈模式保持，训练日列表换成新计划的已完成天。

## 5. 文案

中英双语（spec 008）+ 繁体（spec 018），所有新增文案三套齐。全仓 grep 旧文案「▶ 待看」残留为验收项。

## 验收清单

1. 计划编排顶栏常驻「反馈」按钮，历史栏收起时仍可见；角标 = 当前学员待看视频数，0 时无角标。
2. 点「反馈」：有待看 → 进入反馈模式并播放第一段待看；无待看 → 进入反馈模式、不开视频窗、训练日列表在最底。再点退出。
3. 历史栏入口文案为「反馈 · 待看 N」，旧文案无残留。
4. 反馈模式栏里，训练日列表在待看列表上方，只列本计划已完成的天，按训练日期升序、最近的在最下；未反馈的带小点，已反馈的显示条数。
5. 悬停 / 选中训练日与网格列头（按天排为行头）双向高亮。
6. 选中训练日 → 不用开视频就能写；⌘↵ 发送后学员端反馈列表出现这条（带日期），网页列表追加、标记更新；刷新后仍在。
7. 同一天可连发多条，按时间列出，显示已读 / 未读。
8. 选中训练日时竖屏大窗关闭；点视频后回复区回到视频反馈，013 的视频反馈结果不变。
9. 网格上有整日反馈的天显示「已反馈」标记，悬停看内容，点击进入反馈模式选中该天；两种排版都正确。
10. 反馈接口读取失败时训练日列表仍在、节头可重试，编辑与视频反馈不受影响；发送失败输入不丢。
11. 存量学员（带历史视频反馈、没有整日反馈）打开计划第一屏正常，013 所有验收项不回退。
12. 1440×900 下顶栏按钮、历史栏、竖屏大窗、聊天浮窗互不重叠；简中 / 英 / 繁三种语言检查无叠压。

## 测试 seam

- **`feedbackModel` 纯函数**（已有 `feedbackModel.test.ts`，在旁边加）：输入计划树 + 学员记录 + 反馈列表，输出训练日列表（只含已完成天、日期升序、每天的整日反馈条数）与按天的「已反馈」映射。先红后绿覆盖：未完成 / 未来天被排除、实际日期 ≠ 推荐日期、同天多条、带 `plan_exercise_id` 或 `video_id` 的反馈不算整日、对不上本计划的日期被丢弃。
- **`PlanWorkspace.test.tsx`**（已有，最高层）：顶栏按钮可见性与角标、点击进 / 出反馈模式（有 / 无待看两种）、选中训练日后 ⌘↵ 发出的请求体（`plan_exercise_id`、`video_id` 为 null，`day_date` 为实际日期）、发送后列表与标记更新、读取失败可重试、点日头标记进入并选中。
- 013 现有反馈模式测试全部保持绿。

## Out of Scope

- 不依赖视频的「按动作」文字反馈。
- 学员 App 训练页里显示当天反馈（需要后端与两端，另立）。
- 编辑 / 删除已发反馈；反馈推送通知。
- 给未完成 / 未来的天写反馈（练前叮嘱用动作备注）。
- 角标计入「已练未反馈的天」。
- 手机端教练的任何改动。
