## 现状事实（已核实，plan-web main@62792be / backend staging@6d2e285）

- 连续多天粘贴按相对日偏移落位，`placePlanDayOffsets` 把超出计划范围的天计入 `skipped` 并跳过。
- 网页里只有「草稿且无任何打卡」的计划能改周数（`calendarLocked = 非草稿 || 有打卡行`）；草稿保存时 `plan_patch` 带 `plan_weeks / start_date / end_date`，已发布计划的更新从不发 `plan_patch`。
- 后端 `PATCH /plans/:id` 与 `POST /plans/:id/days/batch` 的 `plan_patch`：只要计划有任何打卡（`planHistoryLocked`），改 `start_date / end_date / plan_weeks` 一律 409 `PLAN_HISTORY_IMMUTABLE`；与发布状态无关。
- 已发布计划带 `days/batch` 的树变更后，后端自动入队 `plan_updated` 推送。
- 已发布计划多天粘贴时，「N 天超出范围已跳过」会被顶栏「已发布未更新」状态文案盖住（既有缺口）。

## 行为

1. 连续多天粘贴有天落在计划末尾之后时，自动在末尾补**整周**，直到所有天都放得下，再按现有规则粘贴；状态栏提示「计划已延长到 N 周」。不弹确认。
2. 适用于草稿、已发布、有打卡的计划。只读编辑器（历史计划、已解绑学员）不适用。
3. 上限 52 周：补到 52 周仍放不下的天照旧跳过，状态栏同时报「计划已延长到 52 周，M 天超出上限已跳过」。
4. 只加不减：不改开始日，不动任何已有的天（含已打卡天）。
5. 一次 ⌘Z 同时撤回这次粘贴和补出的周。延长**已写入服务端之后**再撤销（2026-11-03 David 拍板 A）：
   - 草稿：多出的周连同其中的内容一起从服务端删掉，周数与结束日缩回（草稿本来就能改周数）。
   - 已发布 / 有打卡：粘进去的内容清掉；多出的周保留为空周（只加不减），页面上也显示为空周。
   - 不论哪种，撤销后保存 / 更新、再刷新，页面显示必须与服务端一致；学员端不得残留被撤销的内容。
6. 草稿：照现有自动保存写入周数与结束日。已发布：留在本地，点「更新计划」时一并写入周数与结束日；学员端多出新周，后端按现有逻辑推送「计划已更新」。
7. 单天 / 单个动作粘贴不涉及（目标天总在计划内）。
8. 修复：多天粘贴的跳过 / 延长提示在已发布计划上也必须看得到，不被「已发布未更新」状态盖住。

## 验收清单

1. 草稿 4 周计划，在 W3 D1 粘贴一份整 3 周的复制：计划变成 5 周，内容按偏移落位，状态栏「计划已延长到 5 周」；刷新后周数与内容保持。
2. 同上一次 ⌘Z：内容与周数都回到粘贴前；等自动保存完成后再撤销，刷新后周数与内容仍是粘贴前。
2b. 已发布计划点「更新计划」后再撤销并再次更新：学员端粘贴内容消失，多出的周为空周；刷新编辑器后显示一致。
3. 已发布、**含已打卡天**的计划：同样的粘贴后本地显示延长；点「更新计划」成功（不再 409），学员端（iOS `iPhone 17e` + 安卓模拟器）看到新增的周并收到推送；已打卡的天、开始日不变。
4. 已发布、未点「更新计划」：学员端不变。
5. 超过 52 周：延长到 52 周，超出的天跳过，提示同时说明两件事。
6. 已发布计划上的跳过 / 延长提示可见。
7. 只读编辑器不能粘贴（现状）。
8. 带历史的老教练账号：打开既有计划第一屏正常，打开不触发任何周数写入。
9. 本地全量测试 + `tsc --noEmit` + build 全绿；Opus 浏览器亲验。

## Out of Scope

- 缩短计划、改开始日、在中间插整周。
- 已发布计划手动改周数的 UI（工具栏周数控件仍按现有规则锁定）。
- 单天 / 单动作粘贴的任何变化；跨标签页剪贴板。
