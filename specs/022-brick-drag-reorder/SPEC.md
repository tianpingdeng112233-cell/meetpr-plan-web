## 0. 为什么

教练写完一天后想调动作顺序，现在只有展开该天、找到每行最左 12px 的 ⋮ 才能拖，几乎没人发现；折叠态（扫视态）里的动作块完全不能拖，只能删了重写。

## 现状事实（已核实，main@02a2215）

- **折叠态**：`BlockGrid.tsx` 每天一格，格内每个动作渲染为一个动作块（`.block-brick`），点击 = 选中（⌘/⇧ 多选），在格内空白按下拖 = 框选，点格子 = 展开该天。动作块**没有任何拖动**。
- **展开态**：`DayColumn.tsx` 每行最左有 `.rowdrag`（⋮，12px 宽），按住可在同一天、同一分区内上下拖，插入线 `row-drop-before/after`，跨分区显示 not-allowed。逻辑在 `weekBandModel.ts` 的 `reorderRowsInWeek`，经 `setWeeksWithHistory` 写入，⌘Z/⌘⇧Z 可撤销。
- **分区**由动作库分类决定（`rowTier`：catalog `accessory` → 辅助项，其余 → 主项及变式），不是教练能改的属性；显示永远主项在前、辅助在后。
- **锁定**：一天里只要有一个动作 `hasLogs`（学员已打卡），整天不可拖排（spec 004：已打卡的天保留服务端原槽位）；提示文案 `S.editor.dayLockedForDrag`。
- **顺序真源**：每天的 `day.rows` 数组序。保存时 `orderWeeksForSave` 按分区排好（#142），`reconcile.ts` 按数组序生成 `sort_order`；两端 App 按 `sort_order` 平铺显示。
- **已发布计划**：编辑留在本地，点「更新计划」走 `POST /plans/:id/days/batch`；后端对已发布计划的任何树变更自动入队 `plan_updated` 推送（backend `routes/plans/index.ts`）。
- 键盘没有移动行的快捷键；跨天只能 ⌘C / ⌘V 复制粘贴。

## 术语（写入 `CONTEXT.md`）

- **动作块（brick）**：折叠态里一天格子中的一条动作摘要；展开该天后对应一行编辑行。_Avoid_: 积木、动作卡片、行（指折叠态时）
- **分区（section）**：一天之内「主项及变式」与「辅助项」两段，由动作库分类决定，固定主项在前。_Avoid_: 主辅组、tier（正文）

## 1. 折叠态：拖动作块

- 可拖的动作块悬停时光标为 grab。
- 在动作块上按下并移动 ≥5px 开始拖动；不足 5px 松手仍是现有的点击选中。拖动一旦开始，不触发框选、不展开该天、不触发点击。
- 拖动中：被拖块半透明；在同一天同一分区内的落点画一条插入横线（落在目标块上半 = 之前，下半 = 之后，与展开态一致）；光标 grabbing。
- 无效落点（别的天、别的分区、锁定天、格子外）：光标 not-allowed，不画插入线；松手不变化。拖过分区线时，状态栏提示「主项和辅助项不能混排」。
- 松手生效：写入新顺序，被拖块成为唯一选中项。
- 拖动开始时若有多选：多选收成被拖的这一块，只移动这一块。
- 两种布局（按周 / 按天）行为一致。
- 不可拖的动作块：锁定天的全部动作块（不显示 grab，悬停 title 用 `dayLockedForDrag`）；学员自加的动作块（`data-student-added`，既不可拖也不是落点）；只读计划里的全部动作块。

## 2. 展开态：整行可抓

- 每行非输入区域都能按住拖：序号列（`#`）、⋮ 把手、行内空白。按下移动 ≥5px 开始拖。
- 在输入框、下拉、按钮里按下仍是编辑 / 选字，不触发行拖动。
- 落点、插入线、禁止规则、锁定规则与现状一致（§1 同一套规则）。

## 3. 规则（两态共用）

- 只在当天、所在分区内上下移动；一次一个动作。
- 锁定天整天不可拖；只读计划（历史计划、已解绑学员）不可拖。
- 走现有 `reorderRowsInWeek` + `setWeeksWithHistory`：⌘Z 撤销、⌘⇧Z / ⌘Y 重做。
- 草稿：拖完照现有自动保存。已发布：拖完留在本地，点「更新计划」后写入，学员端由后端现有逻辑收到「计划已更新」推送；本 spec 不新增推送规则。
- 不新增任何顺序字段；只改 `day.rows` 数组序。

## 验收清单

1. 折叠态按周布局：同一天同一分区内把一个动作块拖到新位置，松手后顺序变化；展开该天，编辑行顺序一致。
2. 折叠态按天布局：同第 1 条。
3. 拖到别的天、别的分区、锁定天、格子外：光标 not-allowed，松手无变化；跨分区时状态栏出现提示。
4. 只点不拖：动作块仍是选中（含 ⌘/⇧ 多选）；在格子空白处拖仍是框选；点格子仍展开该天。
5. 多选状态下拖其中一块：只有这一块移动，选中收成这一块。
6. 展开态：从序号列、⋮、行内空白都能拖；在动作名输入框里拖选文字不触发行拖动。
7. 锁定天：折叠态动作块不显示 grab、悬停有原因提示；展开态把手禁用（现状保持）。学员自加块不可拖。
8. ⌘Z 撤销一次拖动、⌘⇧Z 重做。
9. 草稿计划：拖完自动保存，刷新页面后顺序保持。
10. 已发布计划：拖完未点「更新计划」时学员端不变；点后 iOS（`iPhone 17e` 模拟器）与安卓学员端显示新顺序，并收到「计划已更新」推送。
11. 只读计划不可拖。
12. 带历史的老教练账号打开既有计划：第一屏正常，打开本身不改变任何已有顺序、不触发保存。
13. 本地全量测试 + `tsc --noEmit` + build 全绿；Opus 浏览器亲验以上各项。

## 测试 seam

- **规则层（已有，复用）**：`weekBandModel.test.ts` 的 `reorderRowsInWeek` 已覆盖同分区移动、跨分区拒绝、锁定拒绝；本 spec 不改规则，不需新增用例。
- **折叠态拖动（新增，先红后绿）**：沿用 `week-band-ui.test.tsx` 的做法——真实 `PlanEditor` + `blockGridTestUtils` + mock `document.elementsFromPoint`，在 `onSave` 边界断言：拖动作块后保存出的顺序正确；跨分区 / 锁定 / 只读 / 移动不足 5px 时顺序不变且点击选中照旧。
- **展开态整行可抓（扩展已有）**：`tier-sections.test.tsx` 现有拖动用例旁加一条「从序号列起拖」与一条「输入框内按下不起拖」。
- 后端与 App 无 seam（不改）。

## Out of Scope

- 跨天、跨周拖动（继续用复制粘贴）；拖动整天（已有，不动）。
- 主项与辅助项混排；改动作分区。
- 多个动作块一起拖。
- 键盘移动行（5B 已拍不做）。
- 触屏 / 平板拖动。
- 学员 App 端排序；后端任何改动；新增推送规则。

## 屏幕稿

2026-11-02 David「定稿」。原稿（Claude Design，仅 Opus 可开）：https://claude.ai/artifact/9WsSWg1n18nwZnZrTeDePj 。以下为转写，实装以此为准；颜色沿用 `block-grid.css` 现有值（`#111827` 深描边、`#f5f6f8` 块底、`#d1d5db` 虚线），稿只定布局与层级。

### ① 折叠态 · 拖动中（有效落点）
- 所在天格子进入选中描边（同 `.block-cell.is-selected`）。
- 原位置：留一个同高空位——`#fafafb` 底、1px `#d1d5db` 虚线描边、整体 45% 不透明，文字照常显示。
- 手里的块（跟随指针）：白底、1px `#111827` 实线描边、圆角 6、柔和投影（`0 8px 20px rgba(14,23,38,.14)`），不倾斜；宽度与原块一致，水平随指针偏移。
- 插入线：2px `#111827` 横线，两端各一个 6px 实心圆点，画在目标块之间（占位不推开其他块）。
- 光标 grabbing。
- 底部状态栏（拖动全程）：「拖动调整顺序 · 只能在当天同一分区内移动」。

### ② 折叠态 · 无效落点 + 锁定天
- 拖到别的分区 / 别的天 / 格子外：手里的块描边变 `#98A0AC`、80% 不透明；不画插入线；光标 not-allowed（稿中为红色禁止圈示意，实装用系统 not-allowed 光标）。
- 跨分区时状态栏换成 `--warn` 色文字「主项和辅助项不能混排」；离开无效区恢复 ① 的文案。
- 锁定天：动作块外观不变、无 grab 光标；悬停任一动作块出深色气泡（沿用 `.block-brick[data-hint]` 气泡样式）「该日含学员已打卡动作，整天不可拖排」。

### ③ 展开态 · 整行可抓
- 序号列（`#`，宽 28–32）是主要抓手：悬停或拖动中该格显示 ⋮（`--ink` 字、`--tint` 底）替代序号，光标 grab / grabbing。原 ⋮ 把手保留。
- 被拖行 48% 不透明（沿用 `.exrow.row-dragging`）；插入线同 ①（2px 深色 + 两端圆点），画在行与行之间。
- 状态栏文案同 ①；无效落点同 ②。
