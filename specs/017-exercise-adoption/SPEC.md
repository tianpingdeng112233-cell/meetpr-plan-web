# Spec 017 · 管理后台「动作库」收录教练自建动作

状态：2026-10-22 /grill 共识「确认」；屏幕稿 ⑥–⑨ 待「定稿」。T2，依赖后端 spec 053（`MeetPR-backend` 仓 `specs/053-exercise-adoption/SPEC.md`，接口与可见性规则以它为准）与本仓 spec 016（管理后台重做，PR #124）。分支 `feat/017-exercise-adoption`，基于 016 分支；016 合并后 rebase 到 main。

## 背景
教练常自建动作，同一个动作各人写法不同。David 要在后台按出现次数看到这些自建动作，并把它们「收录」进官方动作库：教练和学员照旧看到自己的叫法，但背后指向同一个官方动作。术语见后端仓 `CONTEXT.md`：**收录**、**教练叫法**。

## 范围
1. **动作库页分段**（稿 ⑥）：页头下第一组分段「官方 N / 教练自建 N」。「官方」= 现有使用统计表，行为不变。「教练自建」下第二组分段「待处理 N / 已收录 N」，加搜索框（动作名或教练名）。页头副标题「教练自建的动作可以收录进官方库；收录后教练和学员仍看到自己的叫法」。
2. **待处理表**（稿 ⑥，数据 = `GET /admin/custom-exercises` 的 `pending`）：一行一个归一名组。列：动作名（粗体 `display_name` + 灰字「N 种写法：写法1、写法2」，只有 1 种时显示「1 种写法」）/ 建过的教练（前两位姓名 +「等 N 位」）/ 计划数 / 操作（只有一个「收录」主按钮）。按接口顺序（计划数降序）。页脚灰字见稿。空态「没有待处理的自建动作」。
3. **收录弹窗 · 先推荐**（稿 ⑦，2026-10-22 David 改：一个按钮进入，优先归到已有官方动作）：标题「收录「X」」，说明「N 位教练 · N 种写法 · N 份计划。收录后他们和学员仍看到自己的叫法。」小标题「先看看是不是已有的官方动作」+ 最多 3 个候选官方动作单选（名称 + 类型 · 肌群 · 器械），第一名带「最像」标签并默认选中；下方搜索框「不在上面？搜索其他官方动作」，输入后候选换成搜索结果。底部左侧文字链「都不对，收录为新的官方动作」→ 切到 §4；右侧「取消」+ 主按钮「归到「所选名」」（无选中时禁用）。提交 → adopt（`exercise_ids` = 组内全部行，`target_exercise_id`）。
   - **候选排序**（前端，数据 = `GET /exercises` 的官方动作）：对组内每种写法与每个官方动作的 `name`（及 `name_en`）先做归一（去空白、小写、全角转半角），按以下顺序取分最高的前 3：① 写法经 `src/data/exercise-aliases.json` 解析到该官方名；② 两者互相包含；③ 字符重合度（Dice 系数，按单字）≥ 0.5。都没有命中 → 弹窗直接打开 §4 的新建表单，顶部灰字「没找到相近的官方动作」，不显示「返回推荐」。
4. **收录弹窗 · 新建官方动作**（稿 ⑧）：同一弹窗内切换，顶部「← 返回推荐的官方动作」；小标题「收录为新的官方动作 · 已按用得最多的那条预填」。字段：官方名称、英文名、类型（主项 / 主项变式 / 辅助动作，单选）、主项家族（类型非辅助时出现：深蹲 / 卧推 / 硬拉）、竞技动作（勾选，仅主项）、肌群、器械、动作模式（多选胶囊，肌群与器械至少选一）。预填 = 组内 `plan_count` 最高那条的属性。主按钮「收录为新的官方动作」→ adopt（`new_official`）。切回推荐时已填内容保留。
5. **已收录表**（稿 ⑨，数据 = `adopted`）：按官方动作分组；组头 = 官方名 +「官方」标签 +「N 位教练的叫法挂在这里」；组内行：教练 / 叫「教练叫法」/ 计划数 / 收录时间（`MM-DD HH:mm`）/「撤销」次按钮。撤销直接调 `POST /admin/custom-exercises/unadopt`（单条），不弹确认，成功 toast「已撤销，X 的「叫法」恢复为自建动作」。页脚灰字「撤销后那条恢复成教练自建动作，回到「待处理」；历史计划和训练记录不受影响。」
6. **成功与失败**：收录成功 toast「已把 N 位教练的「X」收录为官方动作」/「已把 N 位教练的「X」归到「目标」」，切到「已收录」并刷新两表与计数。409 `EXERCISE_ADOPTION_CONFLICT`：toast「有动作刚被别处处理过，已刷新列表」并刷新；其他错误沿用现有错误文案，弹窗保持打开、已填内容不丢。
7. **教练端动作库编辑**（无单独稿，沿用现有 `CatalogPage` 样式）：被收录的自建动作（`adopted: true`）在编辑弹窗里只能改名字，其余属性只读并显示一行灰字「已收录为官方动作，属性以官方为准」；不显示「删除」按钮。后端 409 `EXERCISE_ADOPTED_ATTRIBUTES_LOCKED` / `EXERCISE_ADOPTED` 给可读提示。
8. 中英文案同步（`strings-admin.ts` / catalog 相关 strings）。

## Out of Scope
新建动作时提示已有官方动作；通知教练；官方动作导出回 iOS 正典；删除官方动作；App 端改动；撤销确认框。

## 验收清单
1. 动作库页两层分段与计数正确；「官方」分段行为与改动前一致。
2. 待处理表列、排序、写法数、教练名缩写正确；搜索按动作名或教练名过滤。
3. 收录弹窗：候选按 §3 排序、第一名默认选中、搜索可换候选、无候选时直接进新建表单；新建：预填取用量最高那条；类型切换时主项家族/竞技动作出现与隐藏正确；肌群或器械为空时不能提交；提交只发一次请求，body 含组内全部 `exercise_ids` 与 `new_official`。
4. 归到推荐/搜索到的官方动作：按钮文案与禁用态正确，提交 body 含 `target_exercise_id`；两种状态来回切换内容不丢。
5. 成功后 toast、切到「已收录」、两表与计数刷新；该组从待处理消失并出现在对应官方组下。
6. 撤销：只发一次 unadopt，toast 正确，行回到待处理。
7. 409 冲突与其他错误按 §6 处理，弹窗内容不丢。
8. 教练端：被收录动作编辑时只能改名、无删除按钮；未收录动作编辑行为不变。
9. 中英文案完整；lint、全量测试、build 绿。
10. 浏览器实看（Claude 收货）：⑥–⑨ 与稿结构一致；用真实 staging 后端走一遍收录 → 教练端看到自己叫法且官方那条隐藏 → 撤销恢复。
