## 0. 为什么

教练手上都有自己排好的 Excel/WPS 计划。现在的导入只认 Monster 宇一种版式，别的教练导不进来；而且入口藏在「计划 ▾」里，学员还没有计划时根本看不到（David 2026-10-22 截图）。

## 术语（已写入 `CONTEXT.md`）

- **从表格导入**：新建计划的第二种方式，导入 = 新建一份草稿计划。
- **导入存疑**：「待核对行」的第三类，分五种：新建动作 / 进了备注 / 推断数值 / 无日期周 / 无内容周（识别失败后教练选「先空着」的周）。

## 1. 入口（Q3）

- 「新建计划」弹窗顶部分成两种方式：**手动新建**（现在的三步）与 **从表格导入**。学员空状态的「＋ 新建计划」、计划 ▾ 里的「新建计划」都进这个弹窗。
- 删除计划 ▾ 里的「导入 .xlsx」（覆盖当前计划那条路）。教练使用指南第五节同步改写。
- **计划 ▾ 菜单瘦身**（David 2026-10-22 看稿追加）：菜单只剩「切换计划」列表与「＋ 新建计划」。计划设置、重命名、补录过往训练、标记完成（草稿另有删除草稿）收进**每个计划行右侧的「⋯」**，作用于那一行的计划：重命名 / 标记完成 / 删除草稿原地生效；计划设置、补录过往训练先切到该计划再打开。各项出现条件沿用现状（如标记完成只对已发布、删除草稿只对草稿）。教练使用指南第一节同步改写。
- 能力开关：进弹窗时调 `GET /coach/plan-imports/status`；`enabled:false`（海外 / 后端没配模型）时「从表格导入」不出现，弹窗与今天一样。

## 2. 导入流程（屏幕稿定稿后以稿为准）

1. **选来源**
   - 上传文件：拖放或选择，接受 `.xlsx` `.xls` `.csv`；WPS 原生 `.et` 若 SheetJS 能读则一并接受，读不了提示「请在 WPS 里另存为 .xlsx」。
   - **粘贴表格**：一个粘贴框，在 WPS / Excel / 金山文档 / Google Sheets 里选中区域复制后粘进来（读剪贴板的制表符文本；有 `text/html` 表格时优先用它，能保留合并格）。（Q15、Q16）
   - 一行说明：「表格内容将由 AI 识别，不会上传文件名」。（Q6）
   - 剩余次数：「今天还能为 {学员} 导入 N 次」；为 0 时按钮置灰并说明明天恢复。（Q9）
2. **识别结构**（loading）→ 调第一步接口。
3. **选周**（Q4）：列出识别到的每一周（标签 · 日期范围 · 练几天），默认勾**最新的连续一段、最多 12 周**；只能勾连续的周，最多 12。若后端回了 `truncated_rows > 0`，提示「表格较长，只识别了最后一部分」。计划名默认取文件名（只在本地用，不上传），粘贴时默认「导入计划」，可改。
4. **识别内容**（loading，显示「第 x / N 周」）→ 调第二步接口（后端对每周已自动重试 1 次，Q17 B）。
   - **某周仍失败**（David 2026-10-22 追加，只对失败周放开 Q7 的「预览页不改格子」）：在结果摘要里展开该周——一句人话原因（按后端 `reason`：`MODEL_BUSY`「DeepSeek 暂时没响应」/ `OUTPUT_TOO_LONG`「这一周内容太多，没读完」/ `BAD_OUTPUT`「这一周没读懂」/ `REGION_SUSPECT`「这一周的范围可能切歪了」）+ 该周在原表里的格子（带行号列字母，可逐格编辑）。三个动作：「改好了，重新识别」（把改后的 cells 重发第二步，只发这一周）、「这周先空着，进编辑器填」（导入一个空周，整周标导入存疑「无内容周」）、「不导这一周」（若在中间，后面的周顺延，周数减一）。
5. **结果摘要**（Q7、Q12）：N 周 · M 个训练日 · K 个动作；四类导入存疑分别计数（新建动作 X 个，并列出名字）；表里没有日期时在这一步选第一练日期（Q14，复用现有日期选择器）。按钮「创建草稿计划」。
6. **创建**：`createPlan`（`plan_weeks` = 勾选周数，`start_date` = 第一周周一或教练所选日期，星期由表中各周的训练日位置得出）→ 自动新建自定义动作（§3）→ `buildWeeks` → 现有 `reconcile` 保存 → 打开编辑器停在当前周。**导入时不再自动补记过往训练**（David 2026-10-22 选 B，取代 002「导入即默认已完成」）：AI 识别的数可能有错，补记写进 PR / e1RM 基线后撤销不了。改为**首次「发布给学员」**时，若计划里有今天之前、尚无打卡的训练日，确认框里多一项默认勾选「把过去 N 周没打卡的训练记为已完成（计入 PR 基线，不计完成率）」；这些过去的周里还有未确认的导入存疑行时，在该项下方提示「过去的周里还有 M 行导入存疑没看」。勾选则发布成功后调用现有补记接口（`markImportedHistory`）。手动新建的计划同样适用；「⋯」里的「补记过去训练」保留。

识别结果不在预览页逐格改，改动全部进编辑器做（Q7）。

### 2.0 空周（2026-10-24 本地实测补）

默认勾选 = 最新的连续 12 个**有内容的周**（后端已剔除只有日期表头的空周，前端再以 `training_days > 0` 兜底）。第二步结果里若某周没有任何动作，摘要把它当失败周处理（原因「这一周没有训练内容」，可改格重识别 / 不导）；所选周全部没有动作时「创建草稿计划」置灰并提示「这几周没有训练内容」，不建空计划。

### 2.0.1 没读懂的动作要指出来（2026-10-24 David 选 A）

后端按动作容错，每周可能带 `unreadable`（见 backend spec 052）。结果摘要对有 `unreadable` 的周单独一块（不再整周标红）：
- 逐条一句人话，定位到天和原文，例如「W19 周二 · 负重山羊挺身 4×15 rpe 6789 —— 写的是 4 组，但只认出 3 个 RPE」。原文由网页用 `source_cells` 从本地原表取；文案按 `reason` + `detail` 生成（SETS_VALUES_MISMATCH：「写的是 {sets} 组，但只认出 {got} 个 {RPE/重量}」；INVALID_NUMBER：「{值} 不是有效的数字」；MISSING_NAME：「没找到动作名」；MISSING_SETS：「没找到组数」；OTHER：「这一行没读懂」）。
- 下方原表格子里，这些 `source_cells` 标红高亮并自动滚到第一处；教练改格后「重新识别这一周」。
- 另给「跳过这几个动作」：确认后这些动作不导入。该周还有未处理的没读懂动作时「创建草稿计划」置灰并提示「W19 还有 2 个动作没读懂」。
- 整周失败（上游忙等）仍按原来的整周块处理。

### 2.0.2 同类写法归组，改一次全部生效（2026-10-24 David：1A / 3B）

后端每个动作带 `unparsed: [{ field: 'reps'|'intensity'|'weight', text }]`。结果摘要顶部「同类写法」区：按 `field + text` 跨所有已选周归组，每组一行「次数写的是『力竭』· 12 个动作」，教练选一个处理方式后对整组生效：
- 次数栏：填一个次数，或点「力竭」（见下）。
- 强度栏：选 RPE / RIR / 百分比 + 填值，或「不设强度」。
- 重量栏：填公斤数，或「不设重量」。
每组都必须处理完，「创建草稿计划」才可点（3B）；未处理时提示「还有 {n} 类写法没处理」。处理后的值写进对应动作的对应栏，原文仍留在备注。

### 2.0.3 次数「力竭」（2026-10-24 David）

次数输入旁加一个「力竭」按钮，教练点一下即可（编辑器与上面的归组处理共用）。存储：该行每组 `set_type = 'failed'`（数据库早有，从未使用）、`target_reps = 1`（占位，不展示）。网页编辑器与学员端 iOS / 安卓都把 `failed` 组的次数显示为「力竭」；回读计划时 `failed` 组 → 编辑器行次数显示「力竭」。旧版 App 升级前会显示为「1 次」，不出错。

### 2.1 只有 Day1–DayN、没写星期的表（2026-10-23 David 确认）

后端把这类表当作一周返回，每天带 `day_index`（顺序）且 `weekday = null`。结果摘要在「需要注意的」下方出现「表里只写了 Day1–Day{n}，没写星期几」+ 复用手动新建的「① 每周哪几天练 / ② 哪天是 D1」选择器，默认按间隔排开（2 天：一、四；3 天：一、三、五；4 天：一、三、五、六；5 天：一、二、四、五、六；6 天：一到六），已选天数必须等于训练日数，否则「创建草稿计划」置灰。Day1 落在 D1 所选星期，其余按顺序排；第一练日期沿用无日期周的日期选择。动作名后端已转为简体。

## 3. 动作名对不上（Q13）

- 先走现有 `ExerciseIndex.resolve`（catalog 真名 + 别名表精确匹配）。
- 找不到的，在「创建草稿计划」时自动建成该教练的**自定义动作**（`createCustomExercise`）：同一次导入里同名只建一个；该教练已有同名自定义动作则直接复用；后端给了 `family_guess` 时建成对应主项变式，否则按辅助项默认值。
- 这些行在编辑器里标「导入存疑 · 新建动作」，教练可以改绑到库里的动作。

## 4. 编辑器里的导入存疑（Q12）

- 导入时把每行的存疑种类写进编辑器行状态，随快照（pending revision）持久，刷新页面不丢；不写进计划树。
- 并入顶栏 ⚠ 待核对行的计数与「跳到下一个」循环；行上有小标记，悬停说明是哪一种（文案以稿为准）。
- 消失条件：教练改过这一行（动作 / 组 / 次 / 强度 / 备注任一），或在编辑卡里点「确认」。无日期周一类在教练设好日期后整体消失。
- **不拦发布**：发布 / 更新时还有存疑行，弹一次确认「还有 N 行导入存疑没看，仍要发布？」。

### 4.1 存疑收紧（David 2026-10-23 选 A，取代上文「五类都进 ⚠」）

本地实测一次导入出现 40 处待核对，太重。改为：**只有可能让学员练错的两类进 ⚠ 待核对**——「推断数值」（数字在原表里找不到）与「无内容周」（识别失败后先空着的周）。「新建动作」「进了备注」「无日期周」不再打行标记、不计入 ⚠，只在结果摘要里列一句（新建动作照旧列出名字）。结果摘要「推断数值」一行旁加「全部确认」：点了之后导入时这些行不带存疑标记。

## 5. 周数上限 12（Q10）

- 新建计划与计划设置里的周数选项从 3–6 放到 3–12（控件形式以稿为准）。后端早已允许 1–52（migration 0020），学员端已有 12+ 周的导入计划在用，不需要改 App。

## 6. 后端契约要点（详见 backend spec 052）

- `GET /coach/plan-imports/status?trainee_id=` → `{ enabled, daily_limit, remaining_today }`
- `POST /coach/plan-imports` `{ trainee_id, source, sheets:[{name, cells:[[r,c,text]]}] }` → `{ import_id, sheet, truncated_rows, header_region, weeks:[{index,label,start_date,training_days,region}] }`；422 `NO_TRAINING_WEEKS`；429 `IMPORT_DAILY_LIMIT`。
- `POST /coach/plan-imports/:id/weeks` `{ weeks:[{index, cells}], header_cells }` → `{ weeks:[{index,start_date,days:[{weekday,rest,exercises:[{name,sets,reps,intensity_kind,intensity_values,weight_values,note,family_guess,flags}]}]}] }`，单周失败 `{index, error:'PARSE_FAILED', reason}`。
- **强度与重量分两条线**（2026-10-23 本地实测补：教练表常同时写 RPE 和预期重量，旧的单一 `mode/values` 让模型二选一失败、整行降成零组占位）：`intensity_kind` ∈ `rpe | rir | pct | null`，`intensity_values` 逐组（长度 = sets 或 0）；`weight_values` 逐组公斤（长度 = sets 或 0）。两条线都有就都填。前端映射到编辑器行的 `intensity`/`intensityBoxes`（spec 034 行级强度）与 `boxes`（重量）。上限写法如「≤6」填 6、原文留备注；区间「8-9」取下限并留备注。
- 前端负责：单元格只发非空、trim；Excel 日期序列转 ISO；按 `region` 从原表截出每周 cells 与 `header_cells`；**不发文件名**。

## 屏幕稿（2026-10-22 David「定稿」，转写如下，实装以此为准）

通用：沿用 011 编辑器视觉（白底卡片、#111827 主按钮、IBM Plex Sans / Noto Sans SC、数字用 IBM Plex Mono）；编辑器里不用橙色，提示用淡黄 `#FEF3C7`。弹窗宽 600–620，圆角 14，背后编辑区淡化。

**⑮ 新建计划 · 从表格导入（选来源）**
- 标题行：左「新建计划」，右侧分段切换「手动新建 | 从表格导入」（选中项白底加粗）。
- 拖放区（高约 168，虚线框）：上传图标；「把训练表拖到这里，或 选择文件」（「选择文件」带下划线）；小字「.xlsx · .xls · .csv · WPS 表格　·　任何教练的排法都可以」。
- 分隔线文字「或者直接粘贴」。
- 「粘贴表格」多行框，占位「在 WPS / Excel / 金山文档 / Google Sheets 里选中整份计划，⌘C 复制，在这里 ⌘V 粘贴」。
- 底行：左「ⓘ 表格内容将由 AI 识别，不会上传文件名」；右「今天还能为 {学员} 导入 {N} 次」。N=0 时主按钮置灰并改为「今天的次数用完了，明天再来」。
- 按钮：「取消」｜「开始识别」（未选文件 / 未粘贴时置灰）。

**⑯ 选择要导入的周**
- 标题「选择要导入的周」；副行「{文件名或"粘贴的表格"} · 在「{页名}」页识别到 {N} 周」。
- 「计划名称」输入框（文件名默认；粘贴默认「导入计划」）。
- 说明行左「默认勾最新的连续一段 · 只能勾连续的周」，右「已选 {k} 周 / 最多 12 周」。
- 周列表（可滚动，每行高 40）：复选框 · `W{n}`（Mono 粗）· 日期范围 `07/28 – 08/03`（无日期显示「没写日期」）· 右「练 {d} 天」。未勾的行灰字浅底。
- `truncated_rows > 0` 时在列表上方加一行灰字「表格较长，只识别了最后一部分」。
- 按钮：左「← 换一个表格」（文字按钮）｜右「识别这 {k} 周」。

**⑰ 识别完成**
- 标题「识别完成」；副行「{计划名} · W{a}–W{b} · {MM/DD} 起」。
- 三格统计：`{k}` 周 · `{m}` 个训练日 · `{x}` 个动作。
- **失败周**（每个失败周一块，红边浅红底）：
  - 首行「W{n} 没识别出来 · {原因}」，原因按 `reason`：`MODEL_BUSY`「DeepSeek 暂时没响应」/ `OUTPUT_TOO_LONG`「这一周内容太多，没读完」/ `BAD_OUTPUT`「这一周没读懂」/ `REGION_SUSPECT`「这一周的范围可能切歪了」。
  - 说明「下面是表里 W{n} 的原始内容，可以直接改（比如删掉说明文字、把「4组 x8」改成「4*8」），改完重新识别。」
  - 原表格子（高约 132，可滚动）：首行列字母、首列行号（只读灰底），其余格子可编辑。
  - 按钮：「改好了，重新识别」（主）·「这周先空着，进编辑器填」·（右侧文字按钮）「不导这一周」。
- 「需要注意的」（右侧小字「进编辑器后会标出来，计入 ⚠ 待核对」），一张分行卡，每行：淡黄签 · 一句说明 · 右侧计数（Mono 粗）：
  - 新建动作 ——「动作库里没找到，已按原名建成你的自定义动作」，下方列出动作名小灰签；
  - 进了备注 ——「60%top、节奏 310、力竭这类写法，原样放在备注里」；
  - 推断数值 ——「数字在原表里找不到，比如一个重量铺满了 4 组」；
  - 无日期周 ——「表里没写日期」，此行有数时下方出现「第一练日期」选择器（复用新建计划的日期控件）；为 0 时整行灰并写「每一周表里都写了日期」；
  - 无内容周 —— 只在有「先空着」的周时出现：「识别失败后先空着，进编辑器手填」。
- 按钮：左「← 重新选周」｜右「创建草稿计划」（有未处理的失败周时置灰，提示「先处理 W{n}」）。

**⑱ 编辑器里的导入存疑**
- 顶栏「⚠ {n} 待核对」计数含导入存疑；点它在待核对行间循环跳。
- 网格积木里存疑行底色淡黄 `#FEF3C7`、边 `#FDE68A`。
- 编辑卡里存疑行底色 `#FFFBEB`，行尾：淡黄小签（新建动作 / 进了备注 / 推断数值 / 无日期周 / 无内容周）+「确认」小按钮；悬停小签出深色提示，文案示例「动作库里没找到「噩梦硬拉」，已建成你的自定义动作。可以改绑到库里的动作，或点确认。」
- 编辑卡底部提示「改过这一行，或点「确认」，淡黄签就消失」。

**⑲ 计划 ▾ 与手动新建**
- 计划 ▾ 菜单：小标题「切换计划」；每行「计划名 · 右侧 MM/DD · 状态」，行尾「⋯」按钮（当前计划行淡黄底）；分隔线；「＋ 新建计划」。不再有「导入 .xlsx」。
- 点「⋯」在右侧弹出该计划的小菜单：「计划设置（第一练日期 · 周数 · 星期）」「重命名」「补记过去训练」「标记完成」（仅已发布）；草稿多一项「删除草稿」（红字，分隔线下）。名称以代码现有文案为准（`backfillPastTraining`=「补记过去训练」）。
- 手动新建弹窗：标题行同 ⑮ 的分段切换（选中「手动新建」）；「计划名称」独占一行；「周数」独占一行，3–12 共 10 格分段按钮；其余（① 每周哪几天练、② 哪天是 D1、③ 第一练日期、Dx 小签）不变。计划设置弹窗的周数同样 3–12。
