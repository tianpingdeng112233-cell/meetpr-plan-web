- **状态**: Ready（2026-10-30 /grill 六轮共识「确认」）；屏幕稿 2026-11-02 David「定稿」。
- **来源**: 内测教练反馈「20 多个学员，选人要花很多时间」「有些学员已经不跟我练了怎么办」。逐题记录 `~/Projects/scratch/student-rail-unbind-grill-20261030.md`。
- **产品正典**: 本文件。后端改动见 backend `specs/057-coach-unbind-alias`；学员端提示见 meetpr-rn `specs/098-unbind-notice`（iOS 仓同目录镜像）。
- **级别 / 节奏**: T2 / P1。本仓无 CI，合并闸门 = 本地全量测试 + `tsc --noEmit` + build + Opus 浏览器亲验。依赖 backend 057 先部署 staging。

## 0. 为什么

1. **找人慢**：顶栏学员下拉是一张平铺列表，没有搜索、没有排序依据，20+ 学员要一个个看。
2. **不练的学员没处去**：系统里没有「结束关系」，不跟练的学员永远挂在列表里。
3. **「修改学员姓名」越权**：现在改的是学员本人的 `display_name`，学员自己 App 里的名字也跟着变。

## 现状事实（已核实）

- 顶栏学员按钮点开是 `TopBar` 里的下拉菜单（学员列表 + 「修改学员姓名」+「← 总览」）。左侧工作区导航已有「总览」。
- ⌘K 命令面板能按学员名搜，但只匹配汉字；动作搜索已有拼音匹配（`src/features/plan-editor/pinyin.ts`）。
- 师生关系 = 一条 `accepted` 的绑定申请；没有任何解绑接口。教练读学员数据的接口全部要求 accepted。
- 两端学员 App 有绑定关卡：没有 accepted 绑定即停在输入邀请码页。iOS 旧版对绑定状态严格解码，后端不能对外吐新状态值（057 处理）。
- 每个训练日的完成时间后端已有（`plan_day_completions.completed_at`），「今天」按学员时区的训练日算（与总览提醒同一口径）。

## 术语（写入 `CONTEXT.md`）

- **解绑（unbind）**：教练结束与某学员的指导关系。关系记录保留，可由学员重新申请、教练接受而恢复。注意与编辑器「未绑定行」（动作没绑到动作库）是两回事。_Avoid_: 删除学员、归档、结束指导
- **在训学员 / 已解绑学员**：当前有有效绑定的学员 / 曾经绑定、已被解绑的学员。
- **学员备注**：教练给学员起的、只有自己看得到的备注名；不改学员本人的名字。_Avoid_: 改名、学员姓名（指备注时）
- **学员栏**：计划编辑器左侧可折叠的学员列表。_Avoid_: 学员下拉、侧边名单

## 1. 学员栏

- 位置：工作区导航与编辑网格之间，可折叠（折叠按钮在栏顶）；默认展开，折叠状态按浏览器记住（`localStorage`，读写包 try/catch）。
- 栏顶：搜索框。匹配备注名、学员本名、拼音全拼与首字母（复用 `pinyin.ts`）。
- **在训学员**每行：
  - 第一行：备注名（无备注显示本名）；有备注时下方小字显示本名。
  - 状态：「HH:MM 完成」/「今日未练」/「休息日」。
  - 右侧：待看视频数角标，0 不显示。
  - 当前学员高亮。点行即切换学员（沿用现有离开前未保存提示）。
- **排序**（无搜索词时）：
  1. 今天已完成训练的，按完成时间升序（越早越靠上）；一天完成多个训练日取最早一次。
  2. 今天有安排但没练的。
  3. 今天休息（没有安排）的。
  - 第 2、3 组内按显示名拼音升序。
- **已解绑分组**：位于栏底，标题「已解绑 · N」，默认收起，展开状态按浏览器记住。行为灰色，只显示名字与「解绑于 MM/DD」。
- **搜索时**：在训命中照常显示；已解绑命中单独归在「已解绑」分组标题下（即使该分组是收起的也显示命中行）。无命中显示空态。
- 状态数据随学员栏加载；窗口重新获得焦点时刷新一次（与总览一致，不加轮询）。

## 2. 顶栏

- 学员按钮去掉下拉：只显示当前学员的显示名，不可点。
- 「修改学员姓名」移出顶栏（见 §3）；「← 总览」删除（左侧导航已有）。
- 计划下拉不变。

## 3. 右侧学员资料栏

- 姓名处显示显示名；旁边「修改学员备注」：行内编辑，1–100 字，可清空（清空即回到显示本名）。保存失败提示「保存备注失败，请稍后重试」。
- 资料栏最底部「解绑」按钮（次要样式、危险色文字），仅在训学员显示。
- 点「解绑」弹二次确认：
  - 标题：「解绑 {显示名}？」
  - 正文三条：「对方会收到通知」「对方 App 会回到输入邀请码页面，训练记录全部保留」「解绑后你只能查看，不能再编辑或发布计划」。
  - 按钮：「取消」/「确认解绑」。
- 成功后：该学员移入「已解绑」分组；当前页切到只读（见 §4）；toast「已与 {显示名} 解绑」。

## 4. 已解绑学员的只读查看

- 从「已解绑」分组点进：编辑器以只读打开该学员（计划切换、历史、反馈视频都能看），顶栏主按钮位置显示「已解绑 · 只读」，不可点。
- 所有写入入口禁用：编辑格子、新建计划、导入、发布/更新、备注编辑、反馈回复、解绑。
- 不进总览、不计入任何角标/提醒（后端只统计在训学员）。

## 5. 老学员再申请

- 教练的绑定申请列表里，若申请人曾被本教练解绑，申请上加标签「老学员 · 上次解绑于 MM/DD」。仍需教练手动「接受」，不自动接受。
- 接受后该学员回到在训，历史计划、训练记录、备注名全部接上。

## 6. ⌘K 命令面板

- 学员项显示与学员栏一致的显示名，匹配规则同 §1 搜索。已解绑学员可搜到，项尾标「已解绑」。

## 验收清单

1. 学员栏可折叠，刷新后保持折叠状态；搜索能按备注名、本名、拼音全拼、拼音首字母命中。
2. 排序按 §1 三组规则；用 staging 造「两人今天不同时间完成 / 一人有课未练 / 一人休息日」验证顺序与状态文案。
3. 待看视频角标与该学员反馈按钮上的数一致。
4. 顶栏学员不再下拉；「← 总览」不在顶栏；计划下拉照旧。
5. 设置备注后：学员栏、顶栏、资料栏、⌘K 都显示备注名，栏内小字显示本名；学员本人 App 里名字不变。清空备注后恢复显示本名。
6. 解绑：确认弹窗文案如 §3；成功后学员移入已解绑分组，当前页变只读，toast 正确；总览不再出现该学员。
7. 已解绑只读：所有写入入口不可用；计划、历史、视频可看。
8. 学员用邀请码重新申请 → 申请带「老学员」标签 → 接受后回到在训，历史和备注接上。
9. 带历史的老教练账号（20+ 学员）升级后第一屏正常，学员栏加载不明显变慢。
10. 本地全量测试 + `tsc --noEmit` + build 全绿；Opus 浏览器亲验以上各项。

## 测试 seam

- **学员栏模型（纯函数，新建）**：输入学员列表（含状态、备注、绑定状态）与搜索词，输出分组与顺序。排序三组规则、拼音匹配、已解绑归组都在这一层先红后绿。
- `TopBar.test.tsx`（已有）：断言学员按钮无下拉、无「← 总览」。
- 资料栏解绑弹窗与只读态：组件测试各一条（确认后调用解绑接口；只读时写入按钮 disabled）。

## Out of Scope

- 学员主动解绑 / 换教练入口（以后单独做）。
- 解绑后学员继续练完剩余计划（两端绑定关卡不放行，R5 已拍）。
- iOS / 安卓教练端的学员栏与备注名显示（这两端仍显示学员本名）。
- 聊天、反馈收件箱等不走花名册接口的地方显示备注名。
- 合并重复账号；删除账号。

### ① 编辑器默认态（左 → 右五块）
- **顶栏**（高 56）：logo + MeetPR｜「学员 {显示名}」纯文本（无 ▾、不可点）｜计划按钮「计划 {计划名} · MM/DD · N周 ▾」（照旧）｜弹性空白｜反馈（带待看数红角标）｜显示实际｜保存状态｜主按钮（发布/更新计划）。
- **工作区导航**（现有，宽约 168）：总览 / 编辑器 / 跟踪 / 动作库。
- **学员栏**（宽约 252，浅底 `--panel-bg`，右边框）：
  - 栏头：左「学员 · N」（N = 在训人数），右侧方形折叠按钮（左箭头图标，`aria-label="折叠学员栏"`）。
  - 搜索框：占满栏宽，placeholder「搜索姓名 / 备注 / 拼音」。
  - 列表按三组，各组有小号灰色组标题：「今天已完成」「今天有安排」「今天休息」；某组为空则不显示该组标题。
  - 行（最小高 48）：左侧显示名（14px）；有备注时其下一行 11px 灰字本名；右侧状态文字——完成「HH:MM 完成」用 `--ok` 色、未练「今日未练」用 `--warn` 色、「休息日」用 `--mut` 色；状态右侧红色圆角角标 = 待看视频数（0 不显示）。
  - 当前学员行：`--tint` 底 + `--tint-bd` 内描边，名字加粗 `--ink` 色，`aria-current="true"`。
  - 栏底固定一条（上边框分隔）：「▸ 已解绑 · N」，点击展开/收起（`aria-expanded`）。
- **编辑网格**：不改。
- **右侧学员资料栏**（宽约 300）：顶部姓名（18px 粗体）+ 同行右侧文字链「修改学员备注」；其下 12px 灰字「备注只有你看得到，学员 App 里的名字不变」。中间为现有资料内容不变。最底部「解绑」按钮：整宽、白底、`--reject-border` 描边、`--bad` 文字。

### ② 搜索态
- 搜索框聚焦为 `--ink` 描边 + `--tint` 外发光。
- 有搜索词时不再按三组分，改为两组标题：「在训 · N」「已解绑 · N」；行样式同默认态，已解绑命中行灰字并显示「解绑于 MM/DD」。分组收起时已解绑命中照样出现在「已解绑 · N」标题下。
- 无命中：列表区显示空态卡「没有匹配的学员」+ 小字「试试拼音首字母，如 wym」。

### ③ 解绑二次确认
- 居中模态（最大宽 440，圆角 14，遮罩半透明深色），`role="dialog"`。
- 标题「解绑 {显示名}？」；正文三条圆点列表：「对方会收到通知」「对方 App 会回到输入邀请码页面，训练记录全部保留」「解绑后你只能查看，不能再编辑或发布计划」。
- 右下按钮：「取消」（次要）+「确认解绑」（`--bad` 实底白字）。
- 成功后底部居中深色 toast「已与 {显示名} 解绑」。

### ④ 已解绑学员只读
- 顶栏学员名照旧纯文本；计划切换、反馈、显示实际可用；主按钮位置显示灰底不可点「已解绑 · 只读」。
- 学员栏底部「已解绑 · N」展开为列表（▾），当前已解绑学员行灰底高亮；其余已解绑行灰字 +「解绑于 MM/DD」。
- 网格上方工具：「新建计划」「导入」以虚线禁用态显示，旁边灰字「已解绑学员只能查看：计划、历史、反馈视频都可看，格子不可编辑」。网格单元格不可编辑。
- 资料栏：「修改学员备注」变灰不可用；姓名下方灰底标签「已解绑 · MM/DD」；底部说明「不进总览、不计入角标与提醒。学员用邀请码重新申请、你接受后恢复编辑。」；不显示「解绑」按钮。

### ⑤ 申请列表「老学员」标签
- 总览页申请卡片：姓名右侧胶囊标签「老学员 · 上次解绑于 MM/DD」（`--tint` 底、`--tint-bd` 描边、`--ink` 字）。其余卡片结构与按钮沿用现有申请卡，不改按钮文案。
