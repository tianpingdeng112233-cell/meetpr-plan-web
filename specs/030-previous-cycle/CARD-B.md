# 030 卡 B — 上一周期：放开编辑

先读仓根 `CONTEXT.md`（「周期（Block）」「上一周期」「快照」「计划树」「后移」「延长」），再读仓根 `CLAUDE.md`、本目录 `SPEC.md`、`CARD-A.md` 与 `docs/journal/2026-11-16-030-A.md`（卡 A 已上线，本卡在它之上做）。本卡做 SPEC「行为」11–18。

- **级别 / 节奏**: T3 / P1。只动本仓，零后端改动、零新依赖。
- **分支**: `feat/030-previous-cycle-b`（base `main`）。本卡是 Claude 派出的实装作业：**不要 commit、不要 push**，改动留在工作区。
- **JOURNAL**: `docs/journal/2026-11-16-030-B.md`（返修追加在同一文件）。

## 目标

上一周期区和正常编辑计划一样可以改，改动属于上一份计划，由它自己的标题条提交；当前周期的保存、发布、撤销完全不受影响。

## 行为（SPEC 11–18 的落地口径）

1. **可编辑**：上一周期为 `draft` 不会出现（不算上一周期）；为 `published` 时，区内改数字、加删动作、插入删除训练日、后移、右键菜单、同周期内拖动与跨周填充、粘贴，全部与正常编辑一致。标题条不再显示「只读 · 可以查看和复制」。
2. **照旧只读的情形**：上一周期为 `completed` / `paused`，或学员已解绑：整区保持卡 A 的只读表现与文案。含已打卡动作的天不可拖排；周数与开始日不可改（上一周期区不提供周期设置入口）。
3. **分界**：跨周期只能复制粘贴，两个方向都可以；拖动与跨周填充不越过分界（卡 A 已有的限制保留，并覆盖从上一周期往当前周期的方向）。
4. **撤销**：两个周期各有自己的撤销栈。⌘Z / ⇧⌘Z 作用于最近一次点击或聚焦所在的周期。
5. **提交**：上一周期有未提交改动时，标题条显示「未更新 · 学员还看不到这些改动」与主按钮样式的「更新上一周期」（见 `design/States.dc.html` 的 B 态；此时右侧只留「更新上一周期」「折叠」）。点击后走现有的已发布计划更新流程，含自动重试一次与失败弹窗；成功后标题条恢复。顶栏主按钮、顶栏状态文案、⌘S 只管当前周期。
6. **发布确认框**：上一周期有未提交改动时，点顶栏「发布」或「更新计划」先弹确认框（`design/States.dc.html` 的 E）：标题「只发布当前周期「<名>」」（更新时为「只更新当前周期「<名>」」）；正文「上一周期「<名>」还有未更新的改动，这次不会一起提交。发布后可以在它的标题条上点「更新上一周期」。」（更新时把「发布后」换成「更新后」）；按钮「取消」「发布当前周期」/「更新当前周期」。确认后只提交当前周期。
7. **保护**：上一周期的未提交改动与当前周期一样受离开保护（切学员、切周期、切视图、关页面、刷新）和快照保护；刷新后能恢复，并按现有做法提示有未提交的改动。折叠上一周期不丢改动，折叠时标题条仍显示「未更新」与「更新上一周期」。
8. **展开范围与编辑**：「再往前 1 周 / 展开整份 / 折叠」只改变显示范围，不改变上一周期的数据；未显示的周照常参与提交。
9. 三套语言都要有新增文案。

## 做法建议（可调整，偏离请在 JOURNAL 说明理由）

上一周期区由**第二个编辑器实例**承载，而不是把两份计划塞进同一份 `weeks` 状态：复用现有的周状态、撤销、快照、更新计划这一整套，各自独立，天然满足「各归各」。嵌入实例不渲染顶栏、历史栏和只读横幅，只渲染自己的标题条与网格；键盘与焦点按卡 A 已有的「当前活动周期」判定分发。历史栏仍只有一个，跟随活动周期里选中的行。两个实例之间不共享行 id、撤销栈、保存队列。

## 约束

- 不改「学员正在练哪份」的状态显示与判定（`studentPlanCursor`、学员进度徽标相关逻辑）——那一块由 iOS spec 110 的网页适配负责，本卡只读不改；上一周期区不新增这类标记。
- 上一周期没有未提交改动时，不得产生任何写请求（含快照写入）；打开周期的读请求数不得比卡 A 多。
- 「更新上一周期」的写入走现有路径，不新写一套 reconcile；注意后端全局限流 100 req/min 与按天先删后建无原子回滚（见仓根 `CLAUDE.md` ④）。两份计划的提交不得并发：一份在提交时，另一份的提交按钮禁用。
- 没有上一周期时，DOM 与请求必须与卡 A 之前一致。
- 不改「新建计划」对话框、导航、历史栏结构。守仓内 lint 与格式配置（`npm run lint`）。
