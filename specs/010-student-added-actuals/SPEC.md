## 术语(已写入 `CONTEXT.md`)

- **额外组**:教练排的某个动作下,学员在处方组之外多做的组。
- **自加动作**:学员在某个训练日里自己从动作库加练的、计划里没有的动作;只属于那一次训练,不进计划树。

## 1. 数据

- 教练读取学员记录的请求(`src/api/coach.ts`,现发 `scope=plan`)改发 `scope=all`。新后端会多返回自加动作行:`adhoc: true`、`plan_exercise_id: null`、`plan_day_id` = 所属训练日的 id。
- `StudentSetLog` 类型加 `plan_day_id?: string | null`(可选,兼容旧后端)。**旧后端(未部署 050)会忽略 `scope=all`、不返回 `plan_day_id`**——此时页面与今天逐像素一致,不报错。
- 额外组是普通的计划内行:`plan_exercise_id` 非空、`set_index` ≥ 该计划动作的处方组数。今天就可能出现在响应里(接口从未设上限),现状是被当成第 N+1 个「实际」标签、并套用处方偏差配色。
- `groupActualsByExercise` 现在丢弃 `plan_exercise_id == null` 的行——保持这个行为;自加动作另走一个新的归集函数(按 `plan_day_id` 分到训练日、再按 `exercise_id` 分组、组内按 `set_index` 排序、同一组序取 `logged_at` 最新的一条),只收 `adhoc` 且 `plan_day_id` 非空的行。

## 2. 额外组的显示

沿用现有「实际」行(`ActualIntensityLine` / `ActualWeightLine`:小字「实际」+ 小圆角标签):

- 处方组数 = 该行在服务器上的处方组数(有学员记录的行本来就是锁定的,组数不会在本地被改)。
- 组序号 < 处方组数的记录:显示与配色**完全不变**。
- 组序号 ≥ 处方组数的记录(额外组):接在处方组的标签之后,中间插一个小灰字「学员自加」(英文 `Added by athlete`),之后的标签一律用**中性灰底**——不参与「偏差红 / 达标黄」的配色(没有处方可比);失败组、未完成组沿用现有的失败 / 未完成样式。强度那一行同理。
- 没有额外组的行渲染结果与改动前逐字节一致。

## 3. 自加动作的显示

- 位置:所属训练日的计划动作行之后,每个自加动作一行,**只读**。
- 行内:动作名(从动作库解析,解析不到显示 id 的兜底与现有做法一致),其下一行小灰字「学员自加」(英文 `Added by athlete`);组、次的格子显示 `–`;强度格是「实际」加各组 RPE 的中性灰标签(没填显示 `–`);重量格是「实际」加 `重量×次数` 的中性灰标签。整行浅灰底,与可编辑行区分。
- 不可选中、不可编辑、不可拖动、不参与键盘导航的编辑路径;不进计划树与快照;不参与发布门禁、待核对行计数、复制周、后移;不计入该日「N 组 · 总量」的处方统计。
- 只读态(查看已完成 / 他人计划)下同样显示。
- 该训练日没有自加动作时,不渲染任何新增元素。

## 4. 右侧上下文栏及其他

- 上下文栏(`ContextRail`)里展示实际记录的地方:若它按计划动作列组,额外组同样以「学员自加」小字分隔;自加动作不要求在上下文栏出现(本期只保证编辑器网格里看得到)。
- 统计页、视频页里凡是用 `set_index` 去对处方数组下标的地方,逐个核对遇到额外组不越界、不串组;只修真的会错的。
- 跳练(学员本周先结算靠后的训练日):编辑器里各训练日按各自的完成状态显示,不需要新界面;核对一遍凡是假设「前面的天都完成了」的逻辑(锁定判断、「落后」提示之类),有错的修。

## 5. 存量与兼容

- 无本地存储迁移。打开任何一份现有计划,第一屏与改动前一致(除非该学员已有额外组记录——它们从「第 N+1 个带偏差配色的标签」变成「『学员自加』小字后的灰标签」)。
- 新前端 + 旧后端:见 §1,与今天一致。旧前端 + 新后端:旧前端发 `scope=plan`,拿不到自加动作行,行为不变。

## 验收清单

1. 没有任何学员自加记录的计划:编辑器渲染与改动前一致(现有快照 / 断言不改而通过)。
2. 某动作处方 4 组、学员记了 5 组:前 4 个标签配色不变,之后出现「学员自加」小字与 1 个中性灰标签;强度行同理。
3. 额外组是失败组 / 未完成组时沿用失败 / 未完成样式。
4. 某训练日有自加动作(2 组):该日计划动作行之后出现只读行,动作名、「学员自加」小字、`–`、两个灰标签;该行不可编辑、不影响「N 组 · 总量」、不出现在保存 / 发布的请求体里。
5. 自加动作只出现在它所属的训练日(按 `plan_day_id`),不因同日期的别的训练日而串位。
6. 响应里没有 `plan_day_id` 字段(旧后端)时不报错、不渲染新增元素。
7. 中英文两套文案都有。
8. `npm test` 全量、`npx tsc --noEmit`、`npm run build` 通过。
