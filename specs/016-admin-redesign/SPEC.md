# Spec 016 · 管理后台重做（浅色 + 删计划总览）

状态：屏幕稿 2026-10-22 David「定稿」，待实装。分级 T2（单模块、纯前端、用户可见改版），PR 等 David「放行」。

## 背景
管理后台（`src/features/admin/AdminWorkspace.tsx`）是黑底红点缀的旧暗色稿；其中「教练申请」直接复用入驻流程的 `CoachApplicationsSection`，所有申请平铺、待处理不置顶、无筛选。David 10/22 拍板：
- 1A 整体重做：统一表格/卡片，教练申请改「待处理优先 + 状态筛选 + 一行一条」，总览改「待办 + 关键数字」。
- 2A 计划相关全删：「计划总览」tab、总览「最近计划」卡、计划详情页都去掉；用户详情里的计划只显示概要、不可点。
- 网页端不做暗色模式；配色参照教练端计划编辑器（`src/features/plan-editor/components/block-grid.css` 的 `.block-layout`）。

## 范围
1. **导航**：左栏五项，顺序 总览 / 教练申请 / 用户 / 绑定关系 / 动作库；打开后台默认落「总览」。「教练申请」有待处理时右上角显示数字胶囊（近黑底白字）。删除「计划总览」及计划详情页的一切入口与代码。
2. **配色与字体**（全后台，取代 `[data-testid="admin-workspace"]` 的暗色变量块）：
   - 页底 `#F5F6F8`，卡片/左栏 `#FFFFFF`，边框 `#E5E7EB`，行分隔 `#EEF0F3`，强边框 `#D1D5DB`。
   - 文字 `#111827` / 次 `#4B5563` / 弱 `#5C6371` / 最弱 `#9CA3AF`。
   - 主按钮、选中筛选项、数字胶囊：`#111827` 底白字；次按钮：白底 `#D1D5DB` 边框。
   - 状态色：成功 `#10715A` on `#E7F1EE`（边 `#B7D4CC`）；提醒 `#A15C00` on `#FEF3C7`（边 `#F2D9A6`）；ADMIN 小标 `#A81E17`（边 `#E0B4B0`），全后台仅此一处用红。
   - 角色标签：教练 = 近黑底白字；有教练学员 = `#EEF0F3` 底深字；自主训练 = 白底灰边灰字；管理员 = ADMIN 同款红线框。
   - 字体沿用全站 `--font-sans` / `--font-mono`（IBM Plex Sans / Mono）。
3. **统一页头**：去掉现在顶部 56px 面包屑条；每页内容区顶部 = 标题 h1（26px/700）+ 一行灰色副标题 + 右侧「刷新」次按钮。详情页改为左上「← 用户 / 名字」面包屑。加载细条保留（改近黑色）。
4. **总览**（稿 ①）：
   - 「待办」卡：列出待处理教练申请（按提交时间新→旧，最多 5 条），每行「X 申请成为教练」+「学员 N 人 · 设备 · 相对时间提交」+ 右侧「去审核」→ 跳教练申请页（待处理筛选）。标题旁数字胶囊；右上「全部申请 →」。无待处理时卡内显示「没有待办」。
   - 四个数字：教练（内测期全量）/ 学员（有教练 N · 自主训练 N）/ 生效绑定（已接受并生效）/ 待审申请（已通过 N · 已拒绝 N）。「已发布计划」去掉。
   - 「最近注册」通栏表：姓名、角色标签、邮箱、注册日期、箭头；最多 10 行，点击进用户详情；右上「全部用户 →」。
   - 副标题「内测期全量数据 · 更新于 HH:mm」（最后一次成功加载时间）。
5. **教练申请**（稿 ②③④）：
   - 副标题「通过后自动创建教练账号和永久邀请码，并发送欢迎邮件」。
   - 分段筛选：待处理（数字胶囊）/ 已通过 N / 已拒绝 N / 全部 N，默认「待处理」；搜索框按姓名或邮箱过滤。
   - 表格列：申请人（粗体姓名 + 下方等宽邮箱）/ 联系方式（空为「—」）/ 学员数 / 设备（iPhone、安卓、iPhone 和安卓）/ 申请时间（`MM-DD HH:mm`，新→旧）/ 操作（右对齐）。宽度不足时表格横向滚动。
   - 待处理行：「通过」主按钮 +「拒绝」次按钮，点击都先弹确认框，不直接发请求。通过确认框：标题「通过X的教练申请？」+ 三条后果（用该邮箱创建教练账号 / 生成永久邀请码 / 发送欢迎邮件）+「取消」「确认通过」。拒绝确认框：「拒绝X的教练申请？」+「将发送结果邮件。」+「取消」「确认拒绝」。
   - 已通过 / 已拒绝行：姓名旁状态标签，操作「重发邮件」。
   - 邮件未送达（接口返回 `welcome_email_sent === false` 或 `result_email_sent === false`）：该行姓名旁改为提醒色「邮件未送达」标签，「重发邮件」按钮改提醒色；同时底部 toast「已通过X的申请，但欢迎邮件没发出去，请点「重发邮件」」（拒绝/重发时措辞相应调整）。标记只存在于本次页面会话，刷新后消失（后端不存邮件状态，本期不改后端）。
   - 成功 toast：「已通过X的申请，欢迎邮件已发送」/「已拒绝X的申请，结果邮件已发送」/「已重新发送邮件」。失败沿用现有 `errorText` 文案（含「该邮箱已是学员账号」），申请保持原状态。
   - 通过/拒绝成功后该行即时移出「待处理」，左栏与总览的待处理计数同步减少，不必整页刷新。
   - 空态：待处理为空「没有待处理的申请」；其他筛选「没有匹配的申请」。
   - 页脚灰字：待处理筛选下「待处理的申请按提交时间从新到旧排列；处理完会自动移到「已通过 / 已拒绝」。」；其他筛选下「本次操作里邮件没发出去的会标黄，点「重发邮件」补发。」
6. **用户详情**（稿 ⑤）：头部 = 首字头像 + 姓名 + 角色标签 + 等宽「邮箱（无则手机号）· 注册于 日期」；左「基本信息」卡新增「邮箱」一行；右「名下学员 / 绑定教练」可点进对方详情；「相关计划」行只读：计划名 / 状态标签 / N 周 / 创建日期，无箭头、不是按钮、无悬停态，标题旁「N 份 · 仅显示概要」。
7. **用户 / 绑定关系 / 动作库**：换浅色与统一页头（副标题放原来的「共 N 个…」计数），表格列、筛选、搜索、排序行为不变。
8. 中英文案都要（`src/i18n/strings-admin.ts`），删去不再使用的 key（`page.plans`、`plans.*`、`detail.*` 中计划详情专用的、`overview.plans*`、`overview.recentPlans/noPlans`）。

## Out of Scope
- 任何后端改动；邮件发送状态持久化；分页。
- 暗色模式或主题切换。
- 管理员写操作（`ADMIN_WRITE_ENABLED` 保持 false，DangerCard 只需在浅色下不难看）。
- 教练端、学员端、入驻页面（`CoachApplicationPage` 等）的样式。
- 后端 `/admin/plans*` 接口不删（前端不再调用即可）。

## 验收清单
1. 左栏恰好五项、顺序如上，无「计划总览」；全仓 grep `计划总览`、`Plan overview`、`getAdminPlans`、`getAdminPlan(`、`planDetail`、`PlanDetailPage` 在 `src/` 下零命中（测试里断言「不存在」的除外）。
2. 打开后台默认是总览；有 2 条待处理申请时左栏「教练申请」与总览「待办」都显示 2，待办卡列出两条，点「去审核」进入教练申请页且筛选为「待处理」。
3. 总览四个数字为 教练 / 学员 / 生效绑定 / 待审申请，无「已发布计划」；无「最近计划」卡。
4. 教练申请页默认只显示待处理；切换四个筛选、搜索姓名或邮箱均正确过滤，计数正确。
5. 点「通过」/「拒绝」先出确认框且不发请求；确认后只发一次对应 POST；成功后该行离开待处理，左栏与待办计数同步减一，toast 正确。
6. 通过时接口返回 `welcome_email_sent: false`：该行（在「已通过」筛选下可见）显示「邮件未送达」与提醒色「重发邮件」，toast 提示重发；点「重发邮件」POST resend 一次，成功后标记消失、toast「已重新发送邮件」。
7. 审核报错（如 `COACH_APPLICATION_EMAIL_IS_STUDENT`）时显示「该邮箱已是学员账号」，申请仍在待处理。
8. 通过成功仍打点 `coach_application_approved`（与现状一致）。
9. 用户详情：相关计划行不可点击（无 button/link、无箭头）；名下学员仍可点进详情；基本信息含邮箱。
10. 全后台浅色：`AdminWorkspace` 渲染后不再出现暗色变量块；页底 `#F5F6F8`、卡片白；红色只出现在 ADMIN 小标。
11. 用户 / 绑定关系 / 动作库三页原有筛选、搜索、排序与空态行为不变（现有测试不回退）。
12. 中英两种语言下文案完整，无漏翻 key。
13. `npm run typecheck`（或仓内等价）、`npm test`、`npm run build` 全绿。
14. 浏览器实看（Claude 收货）：总览、教练申请四个筛选、确认框、邮件未送达态、用户详情，与稿 ①–⑤ 结构/层级/间距一致；窗口 1280 与 1024 宽下表格不挤坏（横向滚动）。
