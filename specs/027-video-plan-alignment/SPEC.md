# 027 — 视频与计划定位联动

状态：Approved。David 于 2026-11-13 批准 [交互 HTML](design/approved.html) 并要求推进开发。基线 origin/main `90678bd`。一个交付单元，T2 / P1，前端局部交互，保留 026 的视频与沟通布局。

## 目标与验收清单

1. 从动作视频标记、沟通视频列表或历史入口打开/切换当前计划内视频时，对应训练日右边缘定位到浮窗左侧 12px，必要时纵向滚动使当天可见；日期对应使用持久化 day/row identity，沿用反馈关联，不按动作名或日历近似匹配。首列也能贴齐。
2. 播放对应训练日显示清晰选中边框和浅色背景，动作保留视频高亮。播放选中独立于计划编辑/多选，不打开编辑态、不改变处方和选择集。关闭浮窗时清除播放日高亮。
3. 打开期间计划能自由横向浏览，首尾留足滚动空间，最后一列能完整移到浮窗左侧。按周排与按天排均有效。保留触控板、Shift+滚轮和中键平移；在未编辑的计划卡片空白处可用左键拖动浏览，不吞掉按钮点击、动作排序、框选或编辑输入。
4. 用户手动浏览后，播放器、播放目标及播放日选中不变；队列悬停、播放进度、已看状态更新、反馈输入与普通重渲染不自动拉回。显式再次打开/切换视频才重新定位。
5. 关闭视频去掉专用滚动余量，尽量维持当前内容的屏幕位置，在正常滚动范围内钳制。窗口/左右栏尺寸变化重算可用范围；不强行取消用户的手动浏览。无当前计划映射的视频正常播放、不错误选中训练日。
6. 保留只读安全、播放器控件、逐帧/倍速/标注、草稿、沟通/历史切换、现有编辑和发布行为。只有布局与会话状态变化，不写计划或后端数据。

## 测试 seam 与验证

使用现有公开入口：渲染真实 PlanEditor，点击视频标记/反馈入口（或调用既有 EditorFeedbackHandle）并经 API mock 边界提供视频。DOM 测试覆盖播放日高亮与编辑选择分离、切换/关闭/悬停/重渲染行为；几何通过浏览器布局接口可控替身测试。真实浏览器跑应用组件及 HTTP 夹具，在 1280×800、1440×900、1920×1080 验证首列/末列、手动拖动后不拉回、按天排、侧栏/窗口变化与关闭。执行完整 Vitest、TypeScript/build；Standards 与 Spec 独立审查。

## Out of Scope

分栏改版、播放器拖动/缩放、专注批改模式、训练内容/日期/保存规则变化、API/schema/迁移、iOS/Android、真实用户写入。原型的示例控制条与演示数据不进入产品。此次推进开发授权到 PR 交付；合并/部署按任务级别与现有门禁另行处理。
