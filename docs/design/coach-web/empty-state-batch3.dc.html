W0 · Web 通用三态组件规范（墨蓝亮色 v3） 以 admin 面板现有 SkeletonRows / ErrorState / EmptyState 为基准，抽成全站五件套。核心裁决：失败 ≠ 空——凡是请求失败，一律用失败件并带重试，禁止渲染成空态或「—」。W1–W11 全部套用此规范。
1 · 列表骨架 SKELETONROWS
行数 = 预期条数（3–8），条色 #E7EAEE/#EDEFF2，1.4s 呼吸。加载超 150ms 才出现，最短停留 300ms 防闪。只用于首次加载；轮询与后台刷新不闪骨架。
2 · 卡片骨架 SKELETONCARD
用于编辑器区切换学员（W1）、追踪 overview 等卡片位。骨架轮廓 = 真实卡片轮廓，高度一致，杜绝加载完成后跳版。
3 · 失败卡 ERRORSTATE
视频列表没能加载出来 网络或服务出了点问题，不是学员没有上传。 重试 仍然失败？重新登录
标题写「哪块没加载出来」，正文必须排除误判（“不是学员没有上传”）。重试只重发该请求，不整页刷新。次操作（重新登录）永远是弱链接，不做按钮。
4 · 空态卡 EMPTYSTATE
还没有学员申请 学员在 app 里输入你的邀请码后，申请会出现在这里。 去复制邀请码 →
三段式文案：为什么空 → 什么时候会有 → 现在能做什么。禁用「暂无数据」「空空如也」。行动项是 ink 色文字链，不抢主操作的按钮层级。
5 · 行内失败标记 INLINEFAIL（表格单元格三义）
加载中
拉取失败 · 可点重试失败
确实没有数据—
「—」从此只表示事实上没有数据。失败一律用红标（bad 8% 底 + 红字 + ↻），点击=单元格级重试。三者一眼可分，这是 W4 的地基。
使用规则
1失败 ≠ 空。请求失败一律用失败件，禁止渲染成空态、「—」或假 loading。
2失败必带重试，作用域 = 该请求本身，不整页刷新、不登出。
3空态三段式：为什么空 · 什么时候有 · 现在能做什么。
4骨架只出现在首次加载；轮询自愈类失败（W8 收件箱）用行内失败标记，恢复后自动消失。
5数字一律 IBM Plex Mono；色值只用 v3 token（ink #17395C · bad #A81E17 · line #E7EAEE），不新造色。
W4 · 花名册行 · 单元格级三态 总览表 grid 与列不动（150 / 104 / 116 / 84 / 78 / 80 / 1fr），只把每个单元格接上 W0 的三义。最关键的修复：e1RM 拉取失败时绝不能写成「尚无实测或登记值」——失败是网络事实，不是学员数据事实。

判定规则
1三态按单元格判定，不按整行——一行里失败的格标红，其余格照常显示。
2点击红标只重试该字段的请求；同请求覆盖的多个格共享一次重试。
3骨架条宽随列宽（完成率 56px · 数字列 24–30px），高 9px，与文字基线对齐，避免行高跳动。
4「—」保持 faint #98A0AC，不加提示、不可点——它现在是三态里唯一的「事实无数据」。
