# MeetPR 教练网页端 — 实装说明（Claude Code）

参考实现：`MeetPR 教练网页端 C.dc.html`（在浏览器直接打开可交互）

## 总原则

**除「计划编排」一屏外，全部 1:1 照抄参考实现的布局、间距、字号、交互、文案。**
计划编排屏：**颜色/token 必须照抄**，但布局与交互设计你可以自行改进（下面列出必须保住的行为契约）。

---

## 1. 设计 token（全局，禁止改动）

```
墨蓝 ink      #17395C   主色：选中态、按钮、强调数字
浅墨 tint     #EAEFF5   选中行/列头背景
浅墨边 tintBd #C9D6E4
正文 txt      #0E1726
次级 sec      #3F4A5A
弱 mut        #6B7686
更弱 faint    #98A0AC
细线 line     #E7EAEE   / line2 #EDEFF2（行分隔）/ bd #D6DAE0（结构边框）
成功 ok       #10715A   完成率 ≥85%、已反馈、已排
警告 warn     #A15C00   完成率 65–84%、待审、待排
危险 bad      #A81E17   完成率 <65%、RPE ≥8.4、未读角标
页面底        #F6F7F9   工作区底 / #FAFBFC 面板底 / #fff 内容卡
播放区暗底    #0E1726   画面 #1B2534 边 #2A3646
```

**字体**：正文 Noto Sans SC / 系统无衬线；**所有数字、代码、时间、重量一律 IBM Plex Mono**（等宽对齐是这个设计的核心特征，不能用正文字体渲染数字）。
中英/数混排的行用 `font-family:'IBM Plex Mono','Noto Sans SC',monospace`。

**尺寸节奏**：正文 12–13px，标签 10–11px，标题 14–15px。行高 26/28/30/36/44px 这几档，不要自创。圆角：控件 4px、卡片 10px、胶囊 999px。

## 2. 页面骨架（1:1）

```
顶栏 44px：M 标记 · 面包屑 COACH / <屏名> · ⌘K 搜索框 · 头像
├ 左导航 300px 内 172px：工作区标题 + 6 项 + 待排队列 + 底部同步时间
├ 主区（随屏变化）
└ 右侧上下文面板 308px（消息屏隐藏，其余屏常驻）
```

导航六项：总览 / 计划编排 / 消息 / 动作库 / 训练视频 / 学员申请。
角标规则（重要）：**消息、学员申请用红色圆角标（bad 底 + 白字）**；动作库、训练视频用灰色纯数字（faint）。
选中态：tint 底 + ink 字 + 600 字重。**每次只能有一个导航项高亮**。

待排队列：只显示学员名，不显示原因。

## 3. 六屏行为契约

**总览** — 表格 grid `150px 104px 116px 84px 78px 80px 1fr`：编号键帽 / 学员 / 级别·体重 / 完成率（条+百分比，按阈值着色）/ 周总量 / RPE / 距赛 / 下周计划徽章 + 红旗原因 / 「排下周 ↵」（仅待排行显示）。页签：全部学员 12 · 待排 6 · 需关注 4。

**计划编排** — 布局可改，但必须保住：
- 7 天并排列（休息日窄列 64px，训练日 ≥194px），列头显示 周几·日期·主题·「主项 N 组 · 辅项 M 组 · 总重 X kg」
- 单元格逐格可选（动作名/组数/次数/每组强度都是独立单元格），选中格 2px ink 内描边，公式栏显示 `A1 · W31` 引用与当前值
- **信息行分词渲染**：主项 → `1RM 175 · e1RM 175 · 上周 5 × 3 @150`；变式/辅助 → `最佳 115 × 3 · 上周 3 × 3 @110`。必须拆成多个 `nowrap` token 放在 `flex-wrap:wrap` 容器里，**不能是一整条 nowrap 字符串**（会溢出到相邻列）
- e1RM = Epley：`w × (1 + r/30)`，按上周表现的次数 +2 估算 @RPE8，取 0.5kg 步进
- KG / RPE 两种强度类型徽章
- 键盘：Tab 跳格、J/K 上下、⌘K 命令面板
- 三周（W30/W31/W32）纵向堆叠，当前周标注

**消息** — 独立一屏，不是编排器的抽屉。左 300px 会话列表（名字 + 最后一条 + 时间 + 红色未读角标 + 「下一条未读 N」）；右侧全宽聊天：日期分组居中标签、教练气泡 ink 底白字靠右 / 学员气泡浅灰靠左、视频与计划卡片、快捷回复胶囊（⌥1–5）、「引用 A1」、发送 ⌘↵。头部有「打开 TA 的计划」直达编排。
编排器右侧面板同时保留一个「消息」页签作为排计划时的上下文聊天 —— 两处共用同一份会话数据。

**动作库** — 左 224px 分类树（比赛三项与变式 / 上肢 / 下肢 / 躯干…），右表格：中文名 / 英文名 / 类型徽章（主项·变式·辅助）/ 器械 / 主要肌群。计数全部由数据推导，总数 1242 必须与页签、导航角标、分类树自洽。

**训练视频** — 左 312px 片段列表，**日期分组头 sticky 吸顶**（`07-26 周日 · 4 条`），行内容：`动作 重量×次数` + `日期 · 第 N 组 · RPE`+ 待审/已反馈徽章，选中行 tint 底 + 3px ink 左内阴影。右侧：标题栏（含前后切换 N/14）→ 9:16 竖屏播放区（暗底）→ 控制条（暂停 / 时间 / 进度条上标出打点位置 / 0.5–2× 分段速度 / ＋在此处打点）→ 底部一行：反馈输入框 + 发送反馈 ⌘↵，右侧并排「本组数据」「打点 · 3 处」两张卡。

**学员申请** — 申请卡列表 + 接受/拒绝，邀请码区块。

## 4. 数据自洽（踩过的坑）

- 任何计数（组数、条数、动作总数、未读数）**必须由数据数组推导**，不要写死字面量 —— 之前多处出现导航角标与页签数字互相矛盾。
- 学员的 1RM 与计划里的重量必须自洽：`重量 × 次数` 反推的 e1RM 不能显著高于 1RM。
- 完成率/RPE 的着色阈值只有一套（见 token 段），三个地方引用同一个函数。
- 术语：统一用「**完成率**」，不要出现「依从度」。

## 5. 容易做错的地方

1. 数字不用等宽字体 → 整个表格对不齐，设计感全丢
2. 长字符串 nowrap 溢出到相邻列（信息行、备注行）→ 必须分词 + wrap 容器
3. 导航双高亮（消息既是屏又是页签时）
4. 视频复盘做成弹窗 → 应该是嵌在屏内的 master-detail
5. 日期分组用普通文字而非 sticky 吸顶
6. 用彩色渐变、大圆角、emoji → 这套设计是克制的专业工具，禁止

## 6. 交付顺序建议

总览 → 计划编排（最难，先把单元格模型定好）→ 消息 → 训练视频 → 动作库 → 学员申请
